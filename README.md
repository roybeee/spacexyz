# SPATIAL — AI 인테리어 스튜디오

매장 인테리어를 직접 편집하는 3D 웹앱입니다. 사진의 분위기를 반영한 초안부터 소재 교체, 정밀 배치, 문 개폐 확인과 3D 파일 내보내기까지 연결합니다.

처음 사용할 때는 [빠른 사용 안내](QUICK-START-KO.md), 이번 추가 기능은 [2026-09-10 개발 결과](DEVELOPMENT-REPORT-2026-09-10.md)를 참고하세요.

## 구현된 기능

- 예시 OFD 매장과 빈 공간 프로젝트. 같은 실제 3D 장면을 사용하는 간편/정밀 모드.
- 벽·바닥·가구 선택, 개별 면 또는 요소 전체의 소재 교체. 12종 시각화 소재와 실제 PBR 재질. 전체 적용 시 다리 등 부품까지 반영하며, 색상·광택·금속성·무늬 크기·결 방향을 개별 면 또는 전체에 설정합니다.
- 실제 소재 PNG/JPG 업로드와 개인 이미지 보관함. 벽·바닥·가구의 선택한 면/전체에 적용하며 원본 비율, 가로 반복 크기(mm), 회전, 광택을 조절합니다. 문·창문 주변 벽 무늬가 이어집니다.
- 간판 로고 업로드: 투명 PNG와 JPG, 원본 비율 유지, 채움 비율, 발광 표현. 로고·소재 이미지 설정은 디자인 안/JSON 저장에 유지되며 PNG/GLB에 반영됩니다. 읽기·적용 실패 시 내보내기를 막고 재시도를 제공합니다.
- 가구/설비/형태 13종, 이동·회전, mm 치수, 조절 가능한 이동/회전 스냅(기본 50mm/15°), 복제, 숨김, 잠금, 삭제, 실행 취소/재실행.
- Shift 클릭 또는 다중 선택 모드로 여러 가구를 선택해 함께 이동·회전·소재 교체·정렬·복제·숨김·잠금·삭제. 상대 간격을 유지하고 그룹 변환은 한 번에 적용/취소합니다. 경계·잠금·문/창문 제약에 걸리면 전체 변경을 거절합니다.
- 가구·설비 세트 보관함: 선택한 1~30개 요소를 이름·분류·메모와 함께 저장하고 다른 프로젝트에서 재사용합니다. 크기·상대 간격·설치 높이·면별 소재와 GLB 원본 참조를 유지하며, 새 ID를 가진 독립 사본으로 배치합니다.
- 세트의 평면 배치 확인, X/Z 위치·하단 높이·회전, 중앙/벽 근처 배치, 3D 전/후 비교 후 적용. 추가된 요소는 함께 선택되어 즉시 이동할 수 있고 한 번의 실행 취소로 제거됩니다. 기존 가구가 포함된 겹침은 별도로 안내하며 경계 초과는 거절합니다.
- 바로 쓸 수 있는 기본 세트 3종: 2인 테이블, 붙박이 벤치와 테이블 3개, 카운터와 뒤쪽 진열장. 내 세트는 소유자별 100개까지 저장하며 보관함 삭제는 이미 배치한 가구에 영향을 주지 않습니다.
- 배치·소재·외관·조명·사진·분석 출처를 디자인 안 6개까지 보관하고 변경 요약 및 3D 전/후 비교 후 불러옵니다. 클라우드 프로젝트 저장에 함께 포함됩니다.
- A3 치수 평면도: 자동/선택 축척, 요소 번호, 전체 치수·개구부 폭, 상부/숨김 표시 범위, 가구·개구부 전체 목록, 벽·바닥 소재 목록. SVG와 목록 CSV 다운로드 및 브라우저 인쇄/PDF 저장을 지원합니다.
- 외관 편집: 간판 문구·글자 스타일·소재·색상·크기·위치와 발광 표현, 어닝의 폭·수평 돌출·경사 높이·앞단 길이·단색/스트라이프. 간판·어닝 클릭으로 설정을 열고 전/후 비교 뒤 적용합니다.
- 유리 전면 표준 배치: 좌/중앙/우 출입문과 분할 유리창, 차콜·오크·스틸 프레임. 기존 전면 개구부만 교체하고 잠긴 개구부는 거절합니다. 입력 높이에 맞춰 문·창문을 구성하며 사진 인식 결과와 구분합니다.
- 외관 시점에서는 전면을 숨기지 않고 폭·돌출을 화면에 맞춥니다. 시점을 이름과 함께 저장하며 로딩 전 복원 요청과 새 프로젝트 전환을 처리합니다. 간판·어닝은 GLB/PNG/JSON 및 디자인 안에 포함되고, 평면 투영·인쇄 소재 목록에도 반영됩니다.
- 두 모서리 클릭으로 사각형 생성, 높이 입력으로 돌출. 파티션, 원기둥. 두 번째 모서리를 정하기 전 외곽과 실시간 치수를 확인합니다.
- 벽에 연결된 문·창문과 실제 개구부 생성. 벽 범위·개구부 겹침 검증.
- 회전/확대, 단면 보기, 정사영 평면/실내 시점, 카메라 저장. 방 크기 변경 시 평면 화면을 다시 맞춥니다.
- 가구 간격 배열, 벽·중앙 정렬, 다른 가구 기준 간격과 원형 배치. 회전·높이·개구부·열린 문짝을 반영한 겹침 확인.
- 조명 색온도와 밝기. 실제 장면 2K PNG, 전체/선택 GLB 내보내기, JSON 프로젝트 가져오기/내보내기.
- 파티션 여닫이문의 경첩·열림 면·각도, 독립 3D 동작 재생과 샘플 간섭 검사.
- 소재 복사·붙이기와 이름·메모가 있는 개인 소재 보관함. 계정당 100개까지 프로젝트 간 재사용합니다.
- Ctrl/⌘ K 기능 검색, 가구·그룹·레이어 검색과 F 선택 확대. 모바일 기능 찾기를 제공합니다. 사용 안내는 6단계 빠른 시작, 도구 안내, 단축키 탭으로 구성하고 각 시작 단계에서 도구를 바로 엽니다.
- 사진 업로드(R2)와 색상 추출, 3D 소재에 적용, 변경 전/후 미리보기, 전체 변경 적용 및 취소.
- 사진과 입력한 공간 치수로 편집 가능한 가구·소재 초안 생성(API 연결 필요). 생성 후 변경 전/후를 비교하고 새 프로젝트로 적용합니다. 추정 표시와 분석 주의사항을 보관합니다.
- OFD·ODA·카페 방향의 10·15·20평 기본 배치 및 직접 치수 입력. API 없이 동작하며 사진 인식 결과와 구분합니다. 좁은 공간에서 맞지 않거나 겹치는 기본 가구는 제외하고 이유를 표시합니다.
- 명시된 한국어 빠른 명령. API 연결 시 사진의 소재 컨셉 분석과 자연어 편집 제안.
- 현재 3D 실내 또는 외관 장면과 선택한 참고 사진으로 AI 컨셉 이미지 생성. 외관은 간판 문구와 어닝 폭·돌출·무늬를 유지하도록 별도 요청합니다. 기본/고품질, 원본 장면 슬라이더 비교, 시안 보관함, JPG 다운로드. 원본 3D는 유지합니다.
- 외부 정적 GLB 가져오기: 원본 소재 유지, 소재 영역별 교체, 원본 소재 복원, 위치·회전·크기 편집, 복제·배열·GLB 재내보내기. 모델을 다 읽기 전 내보내기는 대기하고, 장면이 바뀌면 중단합니다.
- D1 프로젝트 저장과 목록, 소유자별 접근 검사, 낙관적 버전 충돌 방지.
- 저장·프로젝트 열기·AI 제안의 비동기 결과를 작업 세션과 연결해 다른 프로젝트에 뒤늦게 적용되는 문제를 방지합니다. 요청 본문과 사진 크기를 스트림 단계에서 제한합니다.
- 로컬 임시 복구 초안은 편의용이며 클라우드 저장의 대체물이 아닙니다.

## 실행 구조

- Vinext/React + Three.js. 렌더러는 클라이언트에서 지연 로딩합니다.
- `lib/scene-model.ts`: 버전 1 장면 계약, 치수 검증, 허용된 명령의 원자적 적용.
- `lib/assemblies.ts`, `app/assemblies-dialog.tsx`, `app/api/assemblies`: 세트 정규화·독립 삽입, 배치 미리보기, 요청 ID 기반 재시도와 소유자별 SQL 보관함. `lib/asset-access.ts`는 세트/프로젝트의 모델·이미지 종류와 소유자를 함께 검사합니다.
- `lib/selection.ts`, `lib/design-variants.ts`, `lib/floor-plan.ts`: 원자적 다중 편집, 비재귀 디자인 스냅샷과 복원, 축척 SVG/CSV/인쇄 문서.
- `lib/scene-engine.ts`: 메시 생성, 표면 선택, 변환, 카메라, 렌더/GLB.
- `lib/facade.ts`, `lib/facade-mesh.ts`, `app/facade-dialog.tsx`: 외관 계약·표준 유리 전면, 실측 단위 메시·문자/스트라이프 텍스처, 미리보기 입력.
- `app/studio.tsx`: 편집 상태, 미리보기, 기록, 저장, 반응형 작업 화면.
- `app/api/projects`, `app/api/photos`, `app/api/assets`, `app/api/images`: 인증 사용자 기준의 D1/R2 접근. 현재 장면과 저장한 모든 디자인 안의 사진 소유자, 외부 모델·시안·소재 이미지·로고 참조의 소유자·종류를 저장 시 검증합니다. 전체 프로젝트는 UTF-8 JSON 1.4MB 이내이며 DB 조회는 자산 ID 80개씩 나눕니다.
- `lib/image-assets.ts`, `lib/image-textures.ts`: 이미지 구조/용량 검사와 브라우저 정규화, 인증 파일 디코딩, 실물 비율의 UV 변환 및 GLB 내보내기용 UV 적용.
- `lib/glb.ts`, `lib/model-loader.ts`: GLB 구조·리소스 제한 검사, 원본 정규화, 독립적인 복제 리소스 관리.
- `app/api/render`, `lib/render-contract.ts`: 이미지 편집 API, 입력/출력 제한, 원본과 생성 이미지 보관. 실제 이미지 파일은 R2에 저장하며 키는 서버가 구성합니다.
- `lib/photo-draft.ts`: 사진 분석 결과 계약, 치수 보정·검증, 브랜드 기본 배치.
- `app/api/photo-draft`: 사진 입력과 엄격한 JSON 검증을 사용하는 Hermes / OpenAI 분석, 완료·거절·치수 검증 처리.
- `app/api/ai`: 서버에서 Hermes 또는 OpenAI로 편집 제안 요청. 검증한 명령만 장면에 적용합니다.
- `db/schema.ts`, `drizzle/`: 저장 스키마와 배포 마이그레이션.

## AI 연결

상단 **AI 연결 설정 → Hermes**에서 Orbit에 사용하는 HTTPS 기본 주소(프로필 경로 포함)와 `API_SERVER_KEY`를 등록합니다. SPATIAL은 Hermes의 기존 모델·공급자 인증을 사용하므로 별도 OpenAI 키 없이 문장 편집, 매장 사진 초안, 물체 사진 분석을 요청할 수 있습니다. 사진에는 이미지 입력을 지원하는 Hermes 버전과 모델이 필요합니다.

연결 확인은 인증된 `/v1/capabilities`와 `/v1/models`, 비인증 접근 차단을 검사합니다. 모델 생성 성공이나 사진 품질을 검사하는 버튼은 아닙니다. 사용자별 연결 암호는 서버 `SPATIAL_CONNECTION_KEY`(32바이트 base64)를 이용해 AES-GCM으로 암호화하며 API로 다시 반환하지 않습니다. 키를 임의 교체하면 기존 암호를 읽지 못하므로 백업·이관 없이 교체하지 마세요.

Hermes 요청은 `/v1/runs`와 고유 세션·중복 방지 키를 사용하고, D1에 접수 번호와 결과를 보관합니다. 통신 실패 후 같은 입력으로 다시 요청하면 같은 실행을 확인합니다. 연결 화면의 **최근 Hermes 요청**에서 상태 확인·중지를 할 수 있습니다. 본문이 달라지면 새 요청입니다. 새로고침 후 원래 입력이 복구되지 않으면 이전 결과를 편집 화면에 자동 적용하지 않습니다. 사진·장면은 등록한 Hermes 및 그 모델 제공자에게 전송되며, 사용량은 해당 Hermes 설정을 따릅니다.

완성 이미지 시안 생성은 별도 OpenAI 경로입니다. `OPENAI_API_KEY` 또는 설정의 접힌 **이미지 시안 생성 · OpenAI 연결**에 입력한 세션 키를 사용합니다. `OPENAI_MODEL` 기본값은 `gpt-4.1-mini`, 이미지 생성 모델 기본값은 기존 `gpt-image-2.5-sunburst-2026-09-08`이며 실제 계정의 접근 권한이 필요합니다. Hermes가 없을 때는 OpenAI로 분석·문장 편집도 가능합니다. 세션 OpenAI 키는 페이지 메모리에만 남습니다.

Hermes 연동 구현과 모의 게이트웨이 검증은 완료했습니다. 실제 사용자의 Hermes 주소·연결 암호는 전달되지 않아 등록 및 실제 모델 응답 검증은 완료하지 않았습니다. 자세한 사용법과 범위는 [HERMES-SETUP-KO.md](HERMES-SETUP-KO.md)를 참고하세요.

## 현재 범위와 한계

사진의 팔레트/소재 방향과 보이는 가구를 편집 가능한 장면에 반영합니다. 사진 초안은 사용자가 입력한 방 크기를 기준으로 만든 추정 배치이며, 사진과 같은 형상을 정밀 복원하는 기능은 아닙니다. 단일 사진에서 실측 치수나 숨겨진 형상을 재구성하지 않습니다. 분석은 현재 지원하는 13종 가구·형태로 단순화합니다. 사진 초안에서 공간 밖으로 벗어난 위치는 보정하고 기록하며, 크기 자체가 맞지 않으면 적용을 거절합니다. AI 컨셉 이미지는 현재 3D 배치와 카메라를 우선하고 참고 사진의 소재·분위기를 반영하도록 지시합니다. 생성 결과의 가구 수·배치가 달라질 수 있으므로 원본과 비교해야 합니다. AI 이미지를 편집 가능한 메시로 다시 변환하는 기능은 없습니다. 기본 PNG 내보내기는 WebGL 장면 캡처이며 오프라인 경로 추적 렌더가 아닙니다. 치수 평면도는 벽 중심선 기준의 공간 검토용 개념 도면입니다. A3 용지에 100% 실제 크기로 인쇄할 때 표시 축척이 유효합니다. 외부 모델은 외곽으로, 상부 요소는 평면 투영으로 표시하며 문 개폐 방향은 지정하지 않습니다. 실제 시공용 도면이나 실측 결과가 아닙니다. 외관은 직선형 전면의 간판·고정 어닝 시각화입니다. 입체 채널 문자, 곡면/접이식 어닝, 구조 계산·설치 적합성 판정은 포함하지 않습니다. 유리 전면 생성 시 기존 전면 문·창문은 새 제안으로 교체하며 실행 취소로 복원할 수 있습니다. PDF는 브라우저 인쇄 대화상자에서 저장합니다. 단일 단계의 영구 가구 그룹을 지원합니다. 중첩 그룹·연결 컴포넌트·복잡한 CAD 구속조건은 지원하지 않습니다.

SKP/MAX 직접 편집·양방향 호환, 범용 폴리곤/곡면 모델링, CAD 도면/견적 자동화, UV 펼치기 전용 편집, 협업 댓글·승인, 300개 자산에 대한 성능 목표는 후속 개발 범위입니다. 가져오기 범위는 8MB 이하 자체 포함 GLB 2.0입니다. 정적 삼각형 메시, 배치된 노드를 포함한 정점/삼각형 각각 20만 이하, 메시 150개·노드 400개 이하, 내부 PNG/JPG 텍스처 최대 8개·각 2048×2048 이하입니다. Draco/Meshopt/KTX2·스킨·애니메이션 등은 해제해 내보내야 합니다. 장면당 외부 모델은 20개까지 허용하며 실제 기기의 성능을 보장하는 수치는 아닙니다. GLB는 메시와 PBR 시각화 교환용이며 편집 파라미터는 JSON에 보관합니다. JSON의 모델·시안·소재 이미지·로고는 같은 계정에 저장된 파일을 참조합니다. 다른 환경으로 전달할 때는 완성된 GLB를 사용하세요. 가구 외곽 겹침은 확인용이며 수동 배치에서 강제 차단하지 않습니다. 실제 메시 접촉, 통행 폭, 피난 동선 적합성 판정은 제공하지 않습니다. 공간 경계와 개구부는 검증하지만 시공/법규 적합성을 판정하지 않습니다.

소재·로고 업로드는 정적 PNG/JPG 원본 8MB 이하, 해상도 각 8,192px 이하 및 1,600만 픽셀 이하입니다. 브라우저에서 디코딩 후 최대 2,048px/2MB로 줄여 저장하며 PNG 투명도는 유지합니다. 디자인별 서로 다른 업로드 이미지 8개까지 허용하고 보관함에는 최근 100개를 표시합니다. 서버는 이미지 컨테이너·CRC·치수·용량을 검사하며 압축 픽셀 전체 디코딩은 브라우저에서 수행합니다. 손상 이미지의 디코딩 실패는 오류로 표시하고 내보내기를 막습니다. 외부 GLB의 소재 이미지는 원본 UV 좌표에 적용되므로 입력한 반복 크기와 실제 치수가 다를 수 있습니다. UV가 없는 모델에는 이미지를 적용할 수 없으며 원본 소재 복원으로 돌아갈 수 있습니다. 평면도는 이미지 픽셀을 넣지 않고 이미지 소재/로고 사용 여부를 목록에 표시합니다. GLB 이미지 해상도는 최대 1,024px로 내보냅니다.

세트 저장은 선택한 가구의 복사 작업이므로 잠긴 원본도 보관할 수 있으나 저장된 사본은 잠금이 해제됩니다. 문·창문·숨긴 요소는 선택에서 제외해야 합니다. 세트당 JSON 200KB 이하이며, 배치할 때는 프로젝트 전체의 가구 300개·외부 모델 20개·업로드 이미지 8개·높이/경계 제한을 다시 검사합니다. 세트 보관함은 프로젝트와 별도로 저장됩니다. 가구가 2개 이상인 세트는 삽입할 때마다 독립된 영구 그룹으로 묶입니다. 삽입한 사본은 원본 세트와 자동 동기화되지 않습니다. 평면 미리보기는 외곽 배치 확인용이고 실제 모델/소재는 3D 미리보기에서 확인합니다.

## 가구 그룹 편집 (v8)

- Shift 클릭 또는 다중 선택 버튼으로 가구 2개 이상을 고른 뒤 속성의 **선택한 가구 그룹으로 묶기**를 누릅니다. Ctrl/Cmd+G도 가능합니다. 문·창문, 숨긴 가구, 잠긴 가구는 먼저 선택에서 제외합니다.
- 그룹은 구성 요소 하나만 클릭해도 전체 선택됩니다. 이동·회전·기본 소재 변경·복제·잠금·숨김·삭제가 선택한 구성 전체에 적용되며 실패 시 전체 작업이 거절됩니다. Shift 클릭으로 그룹 전체를 추가하거나 선택 해제합니다.
- 이름은 속성에서 변경하고 체크 버튼으로 저장합니다. **그룹 안 편집**에서 개별 요소의 위치·치수·소재·면별 텍스처를 편집합니다. **편집 완료** 또는 Esc로 전체 선택으로 돌아갑니다. 다른 요소 선택, 실행 취소/다시 실행, 제안 적용, 프로젝트 전환 시 개별 편집 모드는 종료됩니다.
- 장면 목록에 그룹 이름·개수·접기/펼치기·전체 잠금·전체 표시가 나타납니다. 펼친 구성 이름을 누르면 해당 가구의 개별 편집으로 들어갑니다. 일부 멤버가 잠기거나 숨겨져 있으면 전체 이동은 제한됩니다.
- 그룹 전체를 복제하면 새 그룹 ID를 부여합니다. 구성 일부만 복제하거나 개별 배열로 만든 사본은 그룹에서 분리합니다. 저장한 세트의 원래 그룹 ID는 제거하고, 다시 배치할 때 새 그룹을 부여합니다.
- **그룹 해제** 또는 Ctrl/Cmd+Shift+G는 위치와 소재를 유지합니다. 기존 그룹끼리 합치려면 먼저 해제합니다. 그룹 안에서 일부 가구를 삭제해 한 개만 남아도 이름과 그룹 ID는 유지하며 해제할 수 있습니다.
- 클라우드 프로젝트·로컬 복구·JSON·디자인 안은 그룹 ID와 이름을 저장합니다. GLB에는 그룹 이름과 `furnitureGroupId`를 갖는 부모 노드로 내보냅니다. 외부 GLB를 다시 가져오면 하나의 가져온 모델로 취급하며 편집 그룹을 역변환하지 않습니다.
- 내부 간격을 보호하기 위해 그룹 구성원의 일괄 정렬과 AI 문장의 위치·회전·크기 변경은 제한합니다. 전체 위치와 회전은 함께 이동·회전, 개별 치수는 그룹 안 편집을 사용하세요. AI/빠른 명령의 기본 소재 변경은 지원합니다.

검증: `node --test tests/*.test.mjs`는 그룹 계약·선택·복제·GLB 계층과 기존 이미지·모델·세트·소유권 API를 검사합니다. 외부 AI 공급자 호출은 모의 응답을 사용하며 실제 AI 시안 품질 또는 브라우저 상호작용 검사는 포함하지 않습니다.


## 반복 배치·벽 정렬 (v9)

가구 또는 그룹을 선택한 뒤 속성의 **반복 배치·벽 정렬**(단일 가구는 **배열·정렬·겹침 확인**)을 엽니다.

- 반복 배치: 원본 외 추가 1~12회, 외곽 사이 간격 0~5,000mm, 좌·우·안쪽·입구쪽 방향을 지정합니다. 원본 전체의 회전된 외곽 폭/깊이 + 간격으로 이동하므로 선택 구성 내부의 상대 위치·소수 mm 좌표·높이·회전·면별 소재가 보존됩니다. 선택된 기존 그룹은 매 반복마다 서로 독립된 그룹 ID를 받으며, 원래 그룹 없는 선택은 임의로 묶지 않습니다.
- 벽·중앙 정렬: 선택한 구성을 통째로 옮깁니다. 벽 여유 0~2,000mm는 **120mm 벽의 안쪽 면**부터 가구 외곽까지의 거리입니다. 벽 정렬은 다른 축을 유지하고, 중앙 정렬은 외곽 중심을 공간 중앙에 맞춥니다. 크기나 간격을 자동 축소하지 않습니다.
- 평면 미리보기: 기존 가구·선택 구성·배치 결과·새 겹침을 구분하고 변경 전후를 비교합니다. 방향별 최대 반복 횟수는 방 안쪽 공간과 전체 300개 한도를 기준으로 계산하며, 다른 가구나 20개 외부 모델 한도는 최종 후보에서 별도로 검사합니다.
- 적용: **3D에서 확인 → 이대로 적용** 순서로 실제 후보를 적용합니다. 전체 배열/정렬은 한 번에 실행 취소합니다. 닫기 또는 제안 닫기는 원본을 바꾸지 않습니다. 미리보기 중 프로젝트나 장면이 달라지면 적용을 거절합니다.
- 경계·잠금·숨김·부분 그룹 검증: 잠긴/숨긴 요소는 편집을 거절합니다. 그룹 일부만 수정하려면 그룹 안 편집을 사용합니다. 일부 멤버의 배열 사본은 원래 그룹과 분리됩니다. 벽·천장/300개 요소/20개 모델/그룹 ID 중복 등 하나라도 실패하면 전체 변경을 적용하지 않습니다.
- 문·창문은 기존 기능을 유지하여 하나씩 선택하고 연결된 벽 방향으로 ± 배열합니다. 개구부의 벽 끝 100mm 여유와 겹침 검사를 적용하며, 벽·중앙 정렬 대상에는 포함하지 않습니다.
- 겹침 수는 기존과 비교해 새로 생기는 외곽 쌍입니다. 기존 그룹 내부의 겹침이나 다른 위치의 기존 겹침을 신규 문제로 중복 표시하지 않습니다. 평면 미리보기는 외곽 투영이며 실제 메시 간섭·유효 동선 폭·시공 적합성을 판정하지 않습니다.

배열/정렬 회귀 검사는 네 방향 배열·회전한 소수 좌표·실제 벽 안쪽면 거리·그룹 독립성·개구부 배열·장면/프로젝트 변경 거절·중복 정렬의 무변경 처리를 포함합니다.


## 3D 줄자 · 치수 메모 (v10)

- 왼쪽 줄자 도구 또는 **T**를 눌러 가구·벽·바닥 위의 시작점과 끝점을 클릭합니다. 클릭한 두 점 사이의 3D 직선 거리를 저장하며, 격자 스냅을 적용하지 않습니다. 드래그로 시점을 바꿀 수 있습니다. Esc는 첫 점을 취소하고, 첫 점이 없으면 측정을 종료합니다.
- 위쪽 줄자 버튼에서 최대 30개 치수의 이름·표시·삭제·위치 보기를 관리합니다. 직선 거리와 수평 거리, 높이 차, X/Z 차를 구분합니다. 거리 표시는 1mm로 반올림하며 계산·저장 좌표는 소수를 유지합니다.
- 가구 측정점은 요소 ID와 가구 로컬 비례 좌표로 보관합니다. 이동·회전을 따라가며, 크기가 바뀌면 같은 비례 위치로 갱신됩니다. 높이가 고정된 의자 좌석 등 개별 부품의 의미나 특정 메시 정점을 추적하는 방식은 아니므로 형태·치수 변경 후 실제 표면을 확인하고 필요하면 다시 측정하세요.
- 벽·바닥 측정점은 표면의 비례 위치와 실제 표면 두께 방향 오프셋으로 보관합니다. 120mm 벽의 안쪽 면 사이 거리는 방 기준 폭보다 120mm 작게 계산합니다. 문·창문은 연결된 벽의 위치와 방향을 따라갑니다. 가져온 GLB는 모델 로딩이 완료된 실제 표면에서만 측정합니다.
- 가구를 삭제하면 치수 메모는 '연결 대상 없음'으로 남고 숫자·3D 선을 표시하지 않습니다. 실행 취소로 같은 가구를 복원하면 다시 연결됩니다. 숨긴 가구에 연결된 치수선도 3D에서 숨깁니다.
- 프로젝트·임시 복구·JSON·디자인 안에 치수를 보관합니다. 치수가 없는 이전 디자인 안을 복원하면 현재 치수도 해당 안의 상태로 돌아갑니다. 가구 사본을 만들 때 기존 치수를 자동으로 복사하지 않습니다.
- **치수 목록 CSV**에는 이름·연결 상태·두 점 좌표·직선/수평/높이 차를 포함합니다. **치수 포함 PNG**는 현재 시점에 표시 가능한 치수를 함께 저장합니다. 일반 PNG·GLB·AI 캡처에서는 치수선을 제외합니다. 치수는 입력한 3D 모델을 기준으로 하며 실제 현장 실측이나 최소 통행 폭 판정이 아닙니다.

추가 검증은 실제 Three 행렬 및 Float32 바닥/벽 레이캐스트, 연결 좌표 재계산, 고아 치수 복원, 이전 디자인 안 복원, 두 점 선택의 원자적 저장, 오버레이 갱신/리소스 해제, 치수 포함/제외 캡처와 실패 후 복구를 다룹니다. 브라우저 상호작용이나 실제 AI 공급자 호출은 검사하지 않았습니다.


## v11 · 매장 안 둘러보기

- 상단 **둘러보기**에서 편집과 분리된 실내 탐색 화면을 엽니다. 기존 편집 시점과 선택을 유지하고, 뒤쪽 편집 화면의 렌더링은 잠시 멈춥니다.
- 마우스/터치 드래그로 시선을 바꾸고, W/A/S/D로 전후좌우 이동합니다. 방향키 ↑/↓는 전후 이동, ←/→는 시선 회전입니다. 모바일 화면 버튼은 길게 눌러 이동·회전하며 키보드로 버튼을 실행하면 한 걸음씩 이동합니다. Esc로 편집에 돌아갑니다.
- 눈높이 1,200·1,500·1,650·1,800·1,900mm와 3단계 이동 속도를 설정합니다. 평면도의 빈 바닥을 클릭해 시작 위치를 옮기거나 중앙 시작 버튼을 사용할 수 있습니다. 가구 안이나 벽 밖 위치는 거절합니다.
- 회전된 가구 외곽을 250mm 확장한 직사각형과 실내 벽면에서 250mm 떨어진 범위를 사용합니다. 이동 구간 전체를 충돌 검사하고 벽/가구를 따라 미끄러지도록 처리합니다. 식물·펜던트의 돌출 범위, 벽에 붙은 두꺼운 문·창틀도 포함합니다. 숨긴 가구와 눈높이+150mm보다 높은 요소는 제외합니다.
- 가구의 틈·테이블 아래·열린 문은 통과하지 않습니다. 직사각형 외곽으로 보수적으로 제한하므로 정확한 보행/접근성/시공 판정이 아닙니다. 시작 위치 자동 탐색은 150mm 이하 간격으로 수행하며, 찾지 못한 경우 지도의 빈 위치를 직접 선택할 수 있습니다.
- 원하는 시점을 기존 프로젝트 카메라 목록(최대 10개)에 저장하며 위치·방향·화각을 함께 복원합니다. 기존 시점 데이터는 그대로 열립니다. 둘러보기의 65도 화각과 눈높이에서 PNG를 내려받을 수 있으며 캡처 중 이동을 잠깐 고정합니다.
- 실내 보기에는 공간 높이에 맞춘 기본 밝은 천장을 표시합니다. 저장한 실내 시점에서도 같은 천장이 보이며, 실내 이외의 뷰에서는 숨깁니다. 이 천장은 표시용으로 GLB에는 포함되지 않습니다.
- 포인터 취소·창 전환·탭 숨김·종료 시 이동 입력을 해제합니다. 사진 및 실제 AI 생성 경로의 조건은 이전 버전과 같습니다.

검증: 회전된 얇은 파티션을 가로지르는 이동, 벽을 따른 이동, 돌출 모델 범위, 눈높이 변경, 시작 위치, 입력 해제, 시점/화각/천장 복원 및 기존 기능 회귀 검사를 수행합니다. 브라우저 조작을 통한 시각 검수는 수행하지 않았습니다.


## v12 · 용도별 레이어

- 상단 레이어 아이콘 또는 장면 요소 목록의 레이어 버튼에서 가구·문·창문을 분류합니다. 이름과 색상을 지정해 최대 20개를 만들고, 고객 좌석·주방 설비·조명 등의 빠른 이름을 사용할 수 있습니다.
- 가구를 선택한 상태에서 레이어를 만들며 함께 배정하거나, 속성의 레이어 선택란 또는 레이어 목록에서 분류를 변경합니다. 그룹 안 편집 중 한 가구를 선택했어도 그룹 전체가 함께 이동합니다. 서로 다른 레이어의 가구는 같은 레이어로 배정한 뒤 그룹으로 묶습니다.
- 레이어별 표시/잠금 개수와 섞인 상태를 보여주며, 현재 레이어의 요소를 일괄 숨김·표시·잠금·해제합니다. 새로 배정하는 요소는 기존 표시·잠금 상태를 유지합니다. 잠긴 가구의 레이어 변경은 차단하며, 레이어 삭제는 가구의 배치와 잠금 상태를 유지한 채 미분류로 옮깁니다.
- ‘이 레이어만 보기’는 해당 요소를 표시하고 나머지 가구·문·창문을 숨긴 뒤 3D 화면으로 돌아갑니다. 벽·바닥·간판·어닝은 레이어 대상이 아닙니다. 숨겨진 문·창문을 표시할 때 서로 겹치거나 간판과 충돌하면 변경 전체를 거절합니다.
- 레이어 창의 실행 취소/다시 실행은 프로젝트 전체의 편집 이력을 사용합니다. 레이어 작업도 각각 한 번의 실행 취소로 복원됩니다. 숨긴 가구는 선택 상태여도 3D 윤곽선이 표시되지 않습니다.
- 프로젝트 JSON·클라우드 저장·복구 저장·디자인 안에는 레이어와 소속을 보관합니다. 이전 디자인 안에 레이어가 없으면 복원 시 현재 분류도 지웁니다. 같은 장면의 복제·반복 배치는 소속을 유지하고, 다른 프로젝트에 쓰는 가구 세트는 그룹/레이어 연결을 분리해 보관합니다. 새 가구, GLB 가져오기, AI 추가, 사진 초안의 요소는 미분류로 시작합니다.
- GLB 내보내기의 extras에는 레이어 목록과 가구/그룹의 레이어 ID·이름·색상을 넣습니다. 기존 그룹 계층과 좌표를 유지하며, 일반 GLB 가져오기에서는 기존과 같이 하나의 모델로 취급합니다.

검증: 그룹 전체 배정, 혼합 레이어 유효성, 잠금 보호, 표시 상태 유지, 레이어 삭제와 복원, 문 겹침 시 원자적 취소, 복제·세트 이동성, 디자인 안 독립성, GLB 메타데이터, 숨김과 줄자/둘러보기/선택 윤곽선의 연동을 검사합니다. 브라우저 조작을 통한 시각 검수는 수행하지 않았습니다.


## v13 · 가구·설비 수량과 예산

- 상단 계산기 또는 속성 하단 **수량·단가·예산 검토**에서 항목별 개당 단가·메모·예산 포함 여부를 입력합니다. 이름·정확한 규격·모든 소재/마감·레이어·단가 상태가 같은 요소를 묶으며, 각 행의 실제 요소에만 단가를 적용합니다. 그룹의 다른 종류 가구로 확장하지 않습니다. 잠긴 요소가 하나라도 있으면 해당 행 편집을 거절합니다.
- 단가는 원화 정수 0~10억 원입니다. 빈칸은 미입력, 0원은 명시적으로 입력한 금액으로 구별합니다. 예산 제외는 표시/숨김과 별개이며, 기본 전체 합계에는 숨긴 요소도 포함합니다. 레이어·검색·표시 상태 필터는 수량표의 목록 소계만 바꾸고 전체 합계와 디자인 안 비교는 바꾸지 않습니다.
- 단가 입력 당시 규격/소재 설정의 지문을 저장해, 치수·모델 원본·재질/마감이 바뀌면 재검토를 표시합니다. 이동·회전·이름·레이어·표시/잠금 변경은 재검토를 일으키지 않습니다. 메모를 함께 저장하는 ‘단가 확인·적용’은 현재 규격의 단가를 확인한 것으로 처리합니다. 지문은 검토 알림용이며 가격 유효성이나 원가를 보장하지 않습니다.
- 전체 합계는 입력된 개당 단가와 별도 비용을 합산한 금액입니다. 단가 미입력과 재검토 수량을 별도로 표시합니다. 목표 예산(0~1조 원), 별도 비용 12개(각 0~10억 원)를 입력하고, 저장한 디자인 안의 당시 단가·별도 비용과 금액 차이를 비교할 수 있습니다. 세금과 시공비를 자동 계산하지 않습니다.
- 벽·바닥·간판·어닝, 설치·운송 등은 별도 비용으로 직접 입력합니다. 그룹은 개별 요소 수량으로, 가져온 정적 GLB는 내부 물체 수와 관계없이 하나의 요소로 계산합니다. 사진 기반 추정 치수는 실제 제품 규격/단가를 확인해야 합니다.
- 전체 예산 CSV와 인쇄/PDF는 검색 필터와 관계없이 전체 항목, 소재·마감 상세, 단가 상태와 목표/별도 비용을 담습니다. 미입력 금액은 CSV에서 빈칸으로 유지하고, 사용자 문자열은 CSV 수식/HTML 삽입을 방지하도록 처리합니다.
- 프로젝트·복구 저장·JSON·디자인 안에 예산을 보관합니다. 같은 프로젝트의 복제/배열은 단가를 유지하지만 다른 프로젝트용 가구 세트는 견적 정보를 제거합니다. 예산이 없던 디자인 안을 복원하면 현재 목표/별도 비용도 제거합니다.
- 단가 편집은 3D 가구를 다시 만들지 않습니다. AI 공간 편집 공급자에 보내는 장면에서는 단가·예산·저장된 디자인 안을 제외하며, 기존 소재/배치 명령 적용 후에는 프로젝트 견적을 보존합니다.

## 문 개폐·배치·소재 편집 확장

파티션의 **통로·문·창문 편집**에서 문에 좌우 경첩, 앞/뒤 열림 면, 0–120° 각도를 지정할 수 있습니다. 새 문은 개폐 설정이 포함되며, 이전 프로젝트의 중앙 고정 문은 `개폐 설정 사용`을 켤 때 표면 경첩 방식으로 전환합니다. **문 동작 보기**는 독립된 3D 미리보기입니다. 슬라이더·프리셋과 왕복 재생으로 살펴보며, 원본 프로젝트의 각도는 개구부 편집에서 적용해야 저장됩니다. 최대 5° 간격으로 문짝·손잡이의 가구·창틀·자기 파티션·실내 경계 간섭을 검사합니다. 샘플 사이 각도의 연속 무간섭을 보증하지 않으며 자동으로 동작을 멈추지는 않습니다.

열린 문짝과 손잡이의 실제 돌출은 그룹 외곽·피벗, 배열·정렬, 보행, 전역 겹침에 반영됩니다. 같은 벽의 두 문이 교차하면 내부 문 겹침으로 표시합니다. 평면도에는 경첩·문짝·점선 궤적이, 목록/CSV에는 경첩·방향·각도가 포함됩니다. GLB는 저장된 각도의 형상을 내보냅니다. 각도만 변경하면 단가 검토 기준을 유지하고, 경첩이나 설치 방향을 변경하면 재검토합니다. 움직이는 문짝과 손잡이에는 고정 치수 메모를 붙이지 않으며 문틀·벽에서 측정할 수 있습니다.

## 사진 가구 · 제품 목록

오른쪽 속성의 **사진 가구 · 제품 목록** 또는 기능 검색에서 사진 가구를 모아 볼 수 있습니다. 제품명·제조사·제품 코드로 검색하고, 전체 CSV 명세서를 내보내거나 도면에서 선택·제품 정보 수정·세트 보관을 진행합니다. 새 사진 가구를 만드는 흐름도 같은 목록에서 시작할 수 있습니다.

부품형 가구는 같은 그룹·사진 물체 식별자 안에서 부품 번호와 등록 부품 수가 맞을 때 제품 한 개로 표시합니다. 빠진 부품, 중복 부품 또는 서로 다른 제품 정보가 있으면 확인 대상으로 표시합니다. 일반 그룹 전체를 무조건 제품 하나로 세지 않습니다. 여러 사진 가구가 섞인 보관 세트도 제품별 식별자를 유지하며 재배치합니다. 과거에 이미 서로 섞여 식별이 불가능해진 구성은 자동 추측하지 않습니다.

현재 치수는 첫 부품의 방향을 기준으로 한 외곽 치수입니다. 온전한 가구를 회전해도 같은 폭·깊이를 표시하지만, 개별 부품의 회전이나 구조 변경은 실제 외곽 치수에 반영됩니다. 제조사와 코드는 사용자가 입력한 정보이며 자동 인증한 제품 정보가 아닙니다. 기존 수량·예산표는 부품별 집계 방식을 유지합니다.

보관함의 세트 검색은 제조사·제품 코드까지 지원하며, 선택하면 참고사진과 제품 정보를 보여줍니다. 사진 가구 목록에서 보관할 때는 그 제품의 부품만 저장 대상으로 넘기고 제품명을 기본 세트 이름으로 사용합니다. 계정별 사진 접근과 보관함 소유권 검증은 유지합니다.
