# SPATIAL — AI 인테리어 스튜디오

매장 인테리어를 직접 편집하는 3D 웹앱의 두 번째 실행 버전입니다. 기존 기획서의 전체 24주 상용 개발이 완료된 상태는 아닙니다.

## 구현된 기능

- 예시 OFD 매장과 빈 공간 프로젝트. 같은 실제 3D 장면을 사용하는 간편/정밀 모드.
- 벽·바닥·가구 선택, 개별 면 또는 요소 전체의 소재 교체. 12종 시각화 소재와 실제 PBR 재질. 전체 적용 시 다리 등 부품까지 반영하며, 색상·광택·금속성·무늬 크기·결 방향을 개별 면 또는 전체에 설정합니다.
- 가구/설비/형태 13종, 이동·회전, mm 치수, 50mm/15도 스냅, 복제, 숨김, 잠금, 삭제, 실행 취소/재실행.
- 두 모서리 클릭으로 사각형 생성, 높이 입력으로 돌출. 파티션, 원기둥.
- 벽에 연결된 문·창문과 실제 개구부 생성. 벽 범위·개구부 겹침 검증.
- 회전/확대, 단면 보기, 정사영 평면/실내 시점, 카메라 저장. 방 크기 변경 시 평면 화면을 다시 맞춥니다.
- 가구 간격 배열, 벽·중앙 정렬, 회전과 높이를 고려한 가구 외곽 겹침 확인.
- 조명 색온도와 밝기. 실제 장면 2K PNG, GLB 내보내기, JSON 프로젝트 가져오기/내보내기.
- 사진 업로드(R2)와 색상 추출, 3D 소재에 적용, 변경 전/후 미리보기, 전체 변경 적용 및 취소.
- 사진과 입력한 공간 치수로 편집 가능한 가구·소재 초안 생성(API 연결 필요). 생성 후 변경 전/후를 비교하고 새 프로젝트로 적용합니다. 추정 표시와 분석 주의사항을 보관합니다.
- OFD·ODA·카페 방향의 10·15·20평 기본 배치 및 직접 치수 입력. API 없이 동작하며 사진 인식 결과와 구분합니다. 좁은 공간에서 맞지 않거나 겹치는 기본 가구는 제외하고 이유를 표시합니다.
- 명시된 한국어 빠른 명령. API 연결 시 사진의 소재 컨셉 분석과 자연어 편집 제안.
- D1 프로젝트 저장과 목록, 소유자별 접근 검사, 낙관적 버전 충돌 방지.
- 저장·프로젝트 열기·AI 제안의 비동기 결과를 작업 세션과 연결해 다른 프로젝트에 뒤늦게 적용되는 문제를 방지합니다. 요청 본문과 사진 크기를 스트림 단계에서 제한합니다.
- 로컬 임시 복구 초안은 편의용이며 클라우드 저장의 대체물이 아닙니다.

## 실행 구조

- Vinext/React + Three.js. 렌더러는 클라이언트에서 지연 로딩합니다.
- `lib/scene-model.ts`: 버전 1 장면 계약, 치수 검증, 허용된 명령의 원자적 적용.
- `lib/scene-engine.ts`: 메시 생성, 표면 선택, 변환, 카메라, 렌더/GLB.
- `app/studio.tsx`: 편집 상태, 미리보기, 기록, 저장, 반응형 작업 화면.
- `app/api/projects`, `app/api/photos`: 인증 사용자 기준의 D1/R2 접근.
- `lib/photo-draft.ts`: 사진 분석 결과 계약, 치수 보정·검증, 브랜드 기본 배치.
- `app/api/photo-draft`: 사진 입력과 엄격한 JSON Schema를 사용하는 OpenAI Responses API, 완료·거절·치수 검증 처리.
- `app/api/ai`: 서버에서 OpenAI Responses API 호출. 임의 코드를 실행하지 않습니다.
- `db/schema.ts`, `drizzle/`: 저장 스키마와 배포 마이그레이션.

## AI 연결

호스팅의 `OPENAI_API_KEY`를 설정하면 모든 AI 기능이 서버 키를 사용합니다. `OPENAI_MODEL`은 선택 사항이며 기본값은 `gpt-4.1-mini`입니다. 서버 키가 없으면 화면 설정에서 현재 세션에만 키를 입력할 수 있습니다. 키는 프로젝트, 데이터베이스, 로컬 저장소에 넣지 않습니다. 첫 실제 요청에서 유효성을 확인합니다. 요청 시 사진/장면 정보를 OpenAI로 전송하고 해당 계정에 사용료가 부과됩니다.

배포 시 서버 API 키가 제공되지 않았으므로 실제 모델을 호출하는 통합 검증은 수행하지 않았습니다. 키 없이 가능한 색상 추출·기본 명령은 AI 분석으로 표시하지 않습니다.

공식 API 근거: https://developers.openai.com/api/docs/guides/images-vision 및 https://developers.openai.com/api/docs/guides/structured-outputs .

## 현재 범위와 한계

사진의 팔레트/소재 방향과 보이는 가구를 편집 가능한 장면에 반영합니다. 사진 초안은 사용자가 입력한 방 크기를 기준으로 만든 추정 배치이며, 사진과 같은 형상을 정밀 복원하는 기능은 아닙니다. 단일 사진에서 실측 치수나 숨겨진 형상을 재구성하지 않습니다. 분석은 현재 지원하는 13종 가구·형태로 단순화합니다. 사진 초안에서 공간 밖으로 벗어난 위치는 보정하고 기록하며, 크기 자체가 맞지 않으면 적용을 거절합니다. 사진 자체를 생성형 이미지로 다시 그리는 기능은 포함하지 않습니다. PNG는 WebGL 장면 캡처이며 오프라인 경로 추적 렌더가 아닙니다. 평면 보기는 정사영이지만 시공 도면 출력 기능은 아닙니다.

SKP/MAX 직접 편집·양방향 호환, GLB 가져오기, 범용 폴리곤/곡면 모델링, CAD 도면/견적 자동화, UV 펼치기 전용 편집, 협업 댓글·승인, 300개 자산에 대한 성능 목표는 후속 개발 범위입니다. GLB는 메시와 PBR 시각화 교환용이며 편집 파라미터/이력은 JSON에 보관합니다. 가구 외곽 겹침은 확인용이며 수동 배치에서 강제 차단하지 않습니다. 실제 메시 접촉, 통행 폭, 피난 동선 적합성 판정은 제공하지 않습니다. 공간 경계와 개구부는 검증하지만 시공/법규 적합성을 판정하지 않습니다.

## 검증

`node tests/scene.test.mjs`로 기본 장면, 치수/면 저장 복원, 다중 표면 소재, 원자적 실패, 잠금, 개구부 범위/겹침, 호스트 편집, 회전 공간 경계, 입력 형식, 한국어 명령, 90도 이상 회전, 스케치 돌출을 확인합니다. D1 마이그레이션 SQL을 SQLite에 적용하여 소유자 격리와 오래된 버전의 저장 거절을 확인했습니다. `node tests/enhancements.test.mjs`는 기존 프로젝트 재질 호환, 면/전체 마감, 배열·정렬, 겹침, 9개 기본 배치와 최소 크기 공간, 사진 치수 보정·거절, 엄격한 응답 스키마를 확인합니다. `node tests/photo-api.test.mjs`는 실제 라우트·검증 로직에 인증과 외부 AI 응답만 대체해 인증/출처/키 오류, 정상 응답, 거절·미완료·잘못된 치수, 스트림 크기 제한을 확인합니다. 이 검사는 실제 AI 품질 검증을 대체하지 않습니다. TypeScript 검사와 배포 빌드를 수행합니다.

이번 요청에서 브라우저 UI/E2E 테스트는 실행하지 않았습니다. 실제 기기에서 GPU 호환성, 터치 드래그, 사진 업로드와 저장 흐름을 확인하는 파일럿 단계가 필요합니다.
